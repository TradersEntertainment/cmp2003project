1. Structure and why we chose it

We implemented a hash table with separate chaining. A hash table answers every operation in expected time that does not depend on the number of stored words, n. A balanced search tree needs about log₂ n string comparisons (≈12 at n = 5,000), and a sorted array needs O(n) shifts per insert. Because the score is a balanced (harmonic) mean of time and peak memory, we designed every byte of the node. We also measured the alternatives rather than guessing: we wrote seven designs that pass all tests and raced them (31 runs each, median, official formula; each ratio is relative to the best of the set below).

The design wins for three reasons.

  • One allocation per word holds everything. The link, the list ID, a fingerprint, the length and the characters share one block of 14 + L bytes, with no separate Key buffer.
  • A one-byte fingerprint rejects wrong words. A node whose fingerprint differs is skipped after reading one byte, without comparing characters.
  • Growth causes no memory spike. rehash parks all nodes on one temporary list through their own links and releases the old bucket array before allocating the new one. As a result, the peak equals the final table size.

We swept the maximum load factor (1, 1.5, 2, 2.5, 3, 4) and chose 2, the best balance of T and M.

2. Layout

buckets_ : array of 2^k Node* (bucket = hash >> (64-k), top bits)      grow ×2 when count = 2·buckets
node     : [ next 8 B ][ ListId 4 B ][ fingerprint 1 B = low 8 hash bits ][ length varint, 1 B if L<128 ][ L chars ]

The hash reads 8 characters per step: XOR the block in, multiply by an odd 64-bit constant, then shift-xor; a final avalanche round follows. Equality is checked 8 bytes at a time. All unaligned loads use char_traits<char>::copy, which compiles to one load and avoids undefined behaviour. The length is a varint (7 bits per byte), so any length is supported but short words pay one byte.

3. The functions

FunctionWhat it does
StudentIndex()Sets an empty state: no bucket array, count 0. Nothing is allocated until the first put, so an empty object holds no dynamic memory.
put(word, list)Hashes the word and walks its chain. If the word exists, it overwrites the ListId (no duplicate). Otherwise it doubles the table when count = 2·buckets, allocates one node with an owned copy of the characters, and links it at the chain head.
find(word, result)Same walk. On a hit it writes result and returns true. On a miss it returns false with result untouched. It never modifies the structure.
erase(word)Walks with Node** link, the address of the pointer that leads to the current node. *link = node->next unlinks the node from any position; the node is then deallocated and the count decremented. A missing word returns false.
size()Returns the stored counter (const, O(1)).
clear()Frees every chain (reading next before each release), frees the bucket array and resets all fields. It is safe to call twice because deallocate(nullptr) is a no-op, and the object is reusable afterwards.
~StudentIndex()Calls clear(), so every byte is released even if the caller never cleared.
helpershash_of, holds (fingerprint → length → equal_text), make_node/free_chain, word_of (varint decode), rehash (growth without overlap).

4. Complexity

n = number of stored words, L = length of the word passed to the operation, b = number of buckets (n/2 ≤ b ≤ n after the first growth). The expected chain length is ≤ 2 by the load-factor rule.

Total memoryΣ(14 + Lᵢ) + 8·b + 40 bytes (the 40 bytes are the StudentIndex object itself). The peak equals this value because the old and new bucket arrays never coexist.

The worst case requires almost all words to fall into one bucket. With our 64-bit hash this did not occur on any family we tested (sequential numbers, shared 19-character prefixes, all 3-letter words, 4,096-character keys). Bucket occupancy matched the uniform model.

A byte-exact model of our layout (Σ(14 + L) + 8·4096 + 40) predicts the 5,000-key CSV peak as 176,022 bytes, exactly the measured value. That is about 35 bytes per word, 14.6 of which are the characters themselves. On the same workload the typical Record-node design measured 298,782 bytes, and open addressing over a Record array measured 674,190 bytes.

6. Testing

Public suite: --test all passes 20/20 at scales 1–20,000 with 6 seeds. It builds without warnings in our region under -Wall -Wextra -pedantic, with both g++ and clang++, and is clean under AddressSanitizer + UndefinedBehaviorSanitizer. Our tests (student_tests.cpp, 11 groups, 11/11, sanitizer-clean) cover: the empty word; prefix chains across the varint boundaries 127/128 and 16,383/16,384 (up to 70,000 characters); 200,000-character words differing in the first, middle or last byte; bytes 0 and 0xFF inside words; ListId 0 and 2³²−1; caller buffers changed after put; clear, reuse and destruction with exact tracked-memory checks; read-only lookups; a 1.4-million-operation differential test against std::map (6 seeds, 4 key shapes); 200,000 keys; and the search engine on top of the index. A script also confirms that every byte outside the marked region is identical to the template.
